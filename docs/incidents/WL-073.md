# WL-073: Quick backtests stored only the newest 13 trades per cell

- **Work-log item:** [WL-073](../work-log.md)
- **Date:** 2026-10-23
- **Severity:** high (backtest trades lost every day since WL-033; the training data Sheryar asked to keep)

## Context

Sheryar (2026-10-23): "I also noticed you deleted the old data in the back tests. I clearly mentioned never delete it. Now don't restore it but make sure it don't happens in the future." WL-058 (2026-10-22) had removed the run prune and made every delete archive first.

## Symptom

A quick run reported about 1,228 trades while a deep run on the same coins stored 82,776. The Backtests page showed about 13 trades per strategy, style and coin group for every quick run.

## Diagnosis

The database still held all 7 backtest runs and all 4 Arena runs; no stored row had been deleted since WL-058. The loss happened before storage: `backtest._replay` replayed about 1,000 candles per coin, then kept `cell[-per_group:]` (the newest 13 per strategy, style and group, `PER_GROUP` from WL-033's "about 50 trades per style") and dropped the rest without writing them. WL-058 looked for `DELETE` statements and purge jobs; a slice that discards computed data before the insert is not a delete, so the search missed it.

## Fix

`_replay` stores every computed trade (`kept.extend(cell)`); `PER_GROUP` and `TARGET_PER_STYLE` are gone and both depths keep everything. The trades of past quick runs are not rebuilt (Sheryar: do not restore); the deep runs and the cached candles cover the same periods.

## Prevention / follow-ups

- `backend/tests/test_no_data_loss.py`: fails on any `DELETE`, `DROP TABLE`, `TRUNCATE`, `unlink`, `rmtree` or `os.remove` in app code outside `db.archive_and_delete` and a named allow-list of derived caches and temp files, and on a migration that drops or deletes; a planted delete is caught in its own test.
- Test `test_quick_run_stores_every_computed_trade`: the stored count equals what the strategies compute.
- [Decision 0010](../decisions/0010-never-delete-data.md) now says computed data is stored, not cut to a newest few, and names the guard; `CLAUDE.md` too.
- Lesson: "never delete" covers discarding before the write. Search for slices like `[-n:]`, `[:n]` and `LIMIT` on data about to be stored, not only for `DELETE`.
